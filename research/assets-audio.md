## 0. Короткий ответ

| Что | Решение |
|---|---|
| **Симлиш** | **Синтезировать кодом.** Формантный синтез на Web Audio. Ноль ассетов, бесконечное разнообразие, голоса задаются 8 числами. Прототип отрендерен и лежит в `assets-research/audio/simlish-proto/`. |

## 1. СИМЛИШ

### 1.1. Сначала — честная калибровка ожиданий

Симлиш в The Sims — это **живые актёры озвучки**, импровизирующие тарабарщину в
студии. Это не синтез, и синтезом это не воспроизводится. Никакой формантный
синтезатор в браузере не зазвучит как человек.

Чего процедурный путь **реально** достигает: уровень Animal Crossing / Undertale /
Banjo-Kazooie — узнаваемо «речевое» бормотание с внятной эмоцией и различимыми
голосами персонажей. Для игры, где вся графика собрана из кода, это стилистически
честнее, чем сэмплы чужих голосов.

Если критерий приёмки — «неотличимо от The Sims», процедурный путь не подходит и
не подойдёт ни один вариант в рамках CC0/CC-BY. Если критерий — «понятно, кто
говорит и с какой интонацией, и это не раздражает на сотом повторе» — процедурный
путь выигрывает у сэмплов с большим отрывом.

#### Что не так с blip-подходом mumble-voice-lab

Он подаёт **синус** в два `peaking`-фильтра. У синуса нет гармоник — форманты
нечего формировать, фильтры почти не работают. Отсюда характерное «пиликанье»
Animal Crossing.

Чтобы получить настоящий гласный, нужен **гармонически богатый источник**.
Это единственное принципиальное отличие моей схемы от mumble-voice-lab, и оно же
даёт разницу между «блипы» и «бормотание».

### 1.3. Путь Б — готовые библиотеки бормотания

Искал на Freesound по CC0, OpenGameArt, GitHub. Итог: **готовых наборов
эмоциональных вокализаций под CC0/CC-BY, покрывающих нужные эмоции, не нашёл.**

Что есть:
- Разрозненные вздохи/хмыканья/«ага» на Freesound — но это разные люди, разные
  комнаты, разные микрофоны. Собрать из них двух консистентных персонажей нельзя.
- `animalese.wav` из animalese.js — CC BY 4.0, один голос, английские буквы.
- Наборы на itch.io — почти все под собственными лицензиями магазина, не CC.

Плюс фундаментальная проблема сэмплов для нашей задачи: **разнообразие**.
Диалогов с преподавателями будет много, реплики повторяются. Набор из 50 сэмплов
приедается за один сеанс игры. Процедурный синтез с seed от текста реплики даёт
разную озвучку каждой строке бесплатно.

### 1.4. РЕКОМЕНДАЦИЯ: путь А, процедурный

Обоснование по пунктам, которые вы назвали:

1. **Вес** — 0 байт ассетов против неизбежных мегабайт сэмплов.
2. **Лицензии** — свой код, вопрос закрыт навсегда. Ни одного чужого голоса.
3. **Разнообразие** — бесконечное, seed от `hash(имя_персонажа + текст_реплики)`
   даёт детерминированность (одна реплика всегда звучит одинаково) при полном
   отсутствии повторов между репликами.
4. **В духе проекта** — вся графика из кода, звук тоже.
5. **Бонус, которого нет у сэмплов:** тот же синтезатор на низкой громкости,
   с сильным ФНЧ и реверберацией, даёт **гомон толпы в коридоре**. Один движок
   закрывает и диалоги, и walla. Это сильный аргумент.

Риск ровно один: **звучание будет «мультяшным», а не «человеческим».** Принимайте
решение, послушав прототип (раздел 1.7), а не по описанию.

### 1.5. Техническая схема

#### Граф Web Audio на один слог

```
ЗВОНКАЯ ВЕТКА (гласный)
  OscillatorNode          .setPeriodicWave(glottalWave)
    │                     .frequency ← контур F0, три точки на слог
    ▼
  BiquadFilterNode        'peaking'   F1  +13 дБ   .frequency ← локус→цель
    ▼
  BiquadFilterNode        'peaking'   F2  +17 дБ   .frequency ← локус→цель
    ▼
  BiquadFilterNode        'peaking'   F3  +14 дБ
    ▼
  BiquadFilterNode        'lowpass'   3200-5200 Гц, Q 0.7   (наклон тракта)
    ▼
  BiquadFilterNode        'highpass'  90 Гц, Q 0.7
    │
    ├──────────────────────────┐
                               │
ШУМОВАЯ ВЕТКА (согласный)      │
  AudioBufferSourceNode   белый шум
    ▼                          │
  BiquadFilterNode        'bandpass'  f, Q от класса согласного
    ▼                          │
  GainNode                огибающая шума
    │                          │
    └──────────────────────────┤
                               ▼
                          GainNode          огибающая слога
                               ▼
                          StereoPanner
                               ▼
                          [ шина персонажа ]
                               ▼
                          ConvolverNode     IR комнаты (процедурный)
                               ▼
                          GainNode          мастер
                               ▼
                          destination
```

Примерно 8 узлов на слог. Фраза из 10 слогов — 80 короткоживущих узлов за ~2 с.
Web Audio это переваривает без проблем.

#### 1. Источник — это самое важное

```ts
/** Голосовой источник: гармоники ~1/n², т.е. спад -12 дБ/окт, как у
 *  голосовой щели. Обычная пила (1/n, -6 дБ/окт) звучит слишком жужжаще. */
function glottalWave(ctx: BaseAudioContext, harmonics = 40): PeriodicWave {
  const real = new Float32Array(harmonics + 1);
  const imag = new Float32Array(harmonics + 1);
  for (let n = 1; n <= harmonics; n++) imag[n] = 1 / (n * n);
  return ctx.createPeriodicWave(real, imag, { disableNormalization: false });
}
```

Создать один раз на `AudioContext` и переиспользовать: `osc.setPeriodicWave(wave)`.

#### 2. Форманты — таблица русских гласных

Значения для взрослого мужского голоса, Гц. Женский/детский — умножить всё на
`formantScale` (см. голоса).

| Гласный | F1 | F2 | F3 |
|---|---|---|---|
| **а** | 700 | 1150 | 2600 |
| **о** | 480 | 850 | 2500 |
| **у** | 320 | 700 | 2450 |
| **э** | 500 | 1750 | 2550 |
| **и** | 300 | 2200 | 3000 |
| **ы** | 350 | 1450 | 2500 |

Три `BiquadFilterNode` типа `'peaking'` **последовательно**. Параметры — замерены
на прототипе (см. 1.7):

| Форманта | gain | «ширина» BW | Q = F / BW |
|---|---|---|---|
| F1 | **+13 дБ** | 70 Гц | ≈ 10 для /а/, ≈ 4.3 для /и/ |
| F2 | **+17 дБ** | 105 Гц | ≈ 11 для /а/, ≈ 21 → зажать до 14 |
| F3 | **+14 дБ** | 160 Гц | ≈ 16 → зажать до 14 |

```ts
const Q = Math.min(Math.max(F[k] / bw[k], 1.0), 14.0);
```

**F2 и F3 обязаны быть громче F1.** Источник с наклоном -12 дБ/окт хоронит их на
~25 дБ к 2 кГц. С «интуитивными» 13/11/7.5 дБ гласные звучат глухо и неразличимо.
Замер подтвердил: при 13/17/14 дБ огибающая выравнивается, пики стоят на
689/1141/2595 Гц против целевых 700/1150/2600 — попадание в пределах 1-2 %.

Дальше по цепочке:
- `lowpass` на 3200 Гц (мужской) / 5200 Гц (женский), Q 0.7 — наклон тракта;
- `highpass` на 90 Гц, Q 0.7 — убрать бубнёж.

#### 3. Коартикуляция — второй по важности приём

Статичные форманты звучат как орган. Речью это становится, когда **F2 едет** от
позиции согласного (локуса) к цели гласного за первые ~45 мс:

| Класс согласного | Локус (F1, F2, F3) | Буквы |
|---|---|---|
| губные | 400, 800, 2300 | п б м ф в |
| альвеолярные | 350, 1750, 2600 | т д н с з л р |
| задненёбные | 350, 2100, 2500 | к г х |

```ts
f2.frequency.setValueAtTime(locus.f2 * scale, t0);
f2.frequency.exponentialRampToValueAtTime(target.f2 * scale, t0 + 0.048);
```

Если выкинуть из схемы всё, кроме этого, — уже будет похоже на речь.

#### 4. Согласные — шумовая ветка

| Класс | Полоса (f, Q) | Длит. | Приём |
|---|---|---|---|
| **с** | 6200 Гц, Q 2.2 | 75 мс | `bandpass` на белом шуме |
| **ш** | 2900 Гц, Q 1.6 | 80 мс | то же, ниже и шире |
| **ф** | 1600 Гц, Q 0.9 | 65 мс | тише, амплитуда 0.30 |
| **х** | 1300 Гц, Q 0.8 | 70 мс | тише |
| **т** | 4000 Гц, Q 1.5 | 28 мс | тишина 28 мс + всплеск 12 мс, экспонента `e^-6t` |
| **к** | 1900 Гц, Q 1.4 | 35 мс | то же |
| **п** | 900 Гц, Q 1.2 | 30 мс | то же |
| **м н** | — | 50-55 мс | звонкий источник + `lowpass` 480 Гц (носовой мурмур) |
| **л р в** | — | 40-45 мс | просто ещё одна формантная цель, без шума |

Для взрывных: **сначала тишина** (смычка), потом всплеск, потом ~28 мс придыхания,
затекающего в гласный. Тишина перед взрывным — то, что делает «т» похожим на «т».

#### 5. Интонация — контур F0

Три уровня, складываются:

**а) Декларация.** F0 падает на ~2.2 полутона от начала к концу любой фразы. Универсально для всех языков, без этого фраза звучит как список.

**б) Ударение.** +1.1 полутона на ударном слоге слова.

**в) Ядерный тон** — по системе ИК Брызгуновой, на последнем/фокусном слоге:

| Эмоция | ИК | Контур на ядре (start, mid, end), полутоны |
|---|---|---|
| Утверждение | ИК-1 | `+0.5, -1.5, -4.5` — резкое падение |
| Вопрос | ИК-3 | `0, +4.0, +7.5` — резкий взлёт |
| Недовольство | — | `-1.0, -2.4, -5.5` при общем сдвиге вниз на 1.5 |
| Радость | — | `+3.0, +3.6, +1.0` при общем сдвиге вверх на 2-3 |

В Web Audio это `exponentialRampToValueAtTime` на `osc.frequency` через три точки
внутри слога. Не `linearRamp` — слух логарифмичен.

#### 7. Голоса персонажей — 8 чисел

```ts
interface Voice {
  f0: number;            // базовая высота, Гц
  formantScale: number;  // длина тракта: <1 — длиннее/темнее, >1 — короче/светлее
  rate: number;          // множитель длительности слога
  breath: number;        // доля придыхательного шума в источнике, 0..0.25
  range: number;         // глубина интонации
  jitter: number;        // дрожание F0, 0.005..0.03
  tilt: number;          // частота ФНЧ наклона, Гц
  pitchRandom: number;   // случайный разброс по слогам, полутоны
}
```

Пресеты — ровно те, на которых отрендерены примеры из 1.7 (кроме `pitchRandom`:
его в прототипе нет, значения взяты из пресетов mumble-voice-lab как отправная точка):

```ts
const MAREY: Voice = {    // немолодой преподаватель, медленный, с придыханием
  f0: 104, formantScale: 0.97, rate: 1.22, breath: 0.13,
  range: 0.65, jitter: 0.020, tilt: 3200, pitchRandom: 2.4,
};

const ALIEVA: Voice = {   // женский, быстрее, светлее, эмоциональнее
  f0: 196, formantScale: 1.16, rate: 0.92, breath: 0.04,
  range: 1.25, jitter: 0.009, tilt: 5200, pitchRandom: 4.0,
};
```

`formantScale` — это и есть «кто говорит». F0 задаёт высоту, но узнаваемость
голоса даёт именно масштаб формант. Меняя только F0, вы получите того же человека,
говорящего выше.

Ориентиры: мужской 85-155 Гц / scale 0.92-1.02; женский 165-255 Гц / scale
1.10-1.22; студент помоложе — сдвинуть rate к 0.85 и range к 1.3.

#### 8. Сборка слога → слова → фразы

```
слог  = [согласный 28-80 мс] + гласный (95 мс безударный / 135 мс ударный) × rate
        + джиттер длительности ±15 %
слово = 1-3 слога, между слогами пауза 12 мс
фраза = 3-5 слов, между словами 85-175 мс × pauseScale
```

Ударение — на втором слоге слова (или на первом, если слог один).

#### 9. Планирование и производительность

Два варианта, оба рабочие:

- **Реального времени.** Планировать узлы через `ctx.currentTime + offset` по
  схеме lookahead-планировщика (Chris Wilson, «A Tale of Two Clocks»):
  `setInterval(25 мс)`, планировать на 100 мс вперёд. Никаких `setTimeout` для
  тайминга нот. Так делает mumble-voice-lab, работает.
- **Оффлайн-рендер.** Отрендерить фразу целиком в `OfflineAudioContext` в
  `AudioBuffer`, дальше играть одним `AudioBufferSourceNode`. Рендер 2-секундной
  фразы — единицы миллисекунд, сильно быстрее реального времени. Плюсы:
  детерминизм, ноль GC-рывков во время игры, кэш по ключу
  `(персонаж, эмоция, seed)`.

Рекомендую начать с реального времени (проще), перейти на оффлайн, если профайлер
покажет рывки. В R3F особенно важно не создавать узлы внутри `useFrame`.

#### 10. Липсинк бесплатно

Огибающая громкости слога уже посчитана — отдавайте её в `morphTarget` рта или
в масштаб меша челюсти. Синхронизация идеальная по построению, потому что это
буквально один и тот же массив.

### 1.6. Реверберация — процедурный IR

Скачивать импульсные отклики не нужно вообще — а заодно снимается вопрос с их
лицензиями, который я не проверял. Генерируются в 15 строк:

```ts
function makeIR(ctx: BaseAudioContext, seconds: number, decay: number, damping: number) {
  const len = Math.floor(ctx.sampleRate * seconds);
  const ir = ctx.createBuffer(2, len, ctx.sampleRate);
  for (let ch = 0; ch < 2; ch++) {
    const d = ir.getChannelData(ch);
    let lp = 0;
    for (let i = 0; i < len; i++) {
      const t = i / len;
      const s = (Math.random() * 2 - 1) * Math.pow(1 - t, decay);
      lp += (s - lp) * damping;      // однополюсный ФНЧ = поглощение верхов
      d[i] = lp;
    }
  }
  return ir;
}
```

| Локация | seconds | decay | damping | wet |
|---|---|---|---|---|
| Коридор | 1.6 | 2.2 | 0.35 | 0.22 |
| Туалет (кафель) | 1.2 | 1.6 | **0.60** | 0.30 |
| Аудитория | 0.9 | 3.0 | 0.25 | 0.16 |
| Библиотека | 0.6 | 4.0 | 0.15 | 0.10 |
| Лифт | 0.25 | 5.0 | 0.20 | 0.12 |
| Столовая | 1.1 | 2.6 | 0.40 | 0.18 |
| Улица | — | — | — | 0 (без конволвера) |

`damping` — это и есть «материал стен»: 0.6 = голый кафель, 0.15 = книги и ковёр.

## 3. МУЗЫКА

### 3.1. Процедурная генерация — реалистично, и вот насколько

Сомнение обычно в тембре: «без сэмплов не будет рояля». Верно — акустический
рояль синтезом не получить. Но для лаунжа он и не нужен: **FM-электропиано**
в духе DX7-шных электропиано — это два осциллятора, звучит уместно и стоит 0 байт.

Рецепт (соотношение и индекс подобраны мной, не копия заводского патча),
проверен рендером:

```
модулятор: sine, частота = f × 14
           индекс = f × 2.6, огибающая e^(-t/0.11)  ← быстрый спад даёт «тайн»
носитель:  sine, частота = f, FM от модулятора
         + вторая частичная на f × 2.005, амплитуда 0.16 (мерцание)
огибающая: атака 6 мс, спад e^(-t/τ), τ = 1.1 + 2.2·√(200/f)   ← бас тянется дольше
```

В Web Audio: `OscillatorNode` (модулятор) → `GainNode` (индекс) → подключить к
`carrier.frequency`, плюс `GainNode` с огибающей на выходе носителя.

Гармонический движок:
- сетка **ii–V–I** с отклонениями, безрутовые джазовые вольтировки (`maj9` =
  3-5-7-9, `min9`, `dom13`);
- **голосоведение**: каждый голос ищет ближайшую октаву к предыдущей позиции,
  движение ≤ 2-3 полутона. Без этого аккорды «прыгают» и слышно машину;
- мелодия — ступени лада поверх аккорда, длительности из взвешенного набора,
  **много пауз**. Плотность нот — главный регулятор навязчивости;
- темп 52-88 BPM, регистр и плотность разные по локациям.

Три отрендеренных примера в `assets-research/audio/music-proto/`:

| Файл | Настройка | Для чего |
|---|---|---|
| `music-proto-lounge.mp3` | 68 BPM, плотность 0.5 | общий фон, дух The Sims |
| `music-proto-library-sparse.mp3` | 52 BPM, плотность 0.22, регистр -1 | библиотека, ночь |
| `music-proto-canteen-bright.mp3` | 88 BPM, плотность 0.62 | столовая, день |

Опять же: спектрально и гармонически это корректно, **но насколько приятно —
слушайте сами.**

**Tone.js брать не советую.** Он MIT и хорош, но ~150 КБ gzip ради нескольких
осцилляторов и планировщика — это дороже, чем 300 строк чистого Web Audio, которые
вы всё равно напишете для симлиша и атмосферы. Один звуковой стек вместо двух.

   Текущие MP3 в `assets-research/` — исследовательские, не продакшен.
5. Если генеративная музыка не пройдёт приёмку — брать 6 CC0-треков и не связываться
   с CC BY, чтобы не заводить титры.

### Оценка веса итогового билда

| Вариант | Вес аудио |
|---|---|
| Всё процедурно + дискретные сэмплы в Opus | **~1.5-2.5 МБ** |
| То же + 6 готовых музыкальных треков в Opus 96 кбит/с | ~10-12 МБ |
| Всё готовыми ассетами | 25-40 МБ |
